# 实现说明与验收

## 参考站点观察

已在浏览器中实际操作参考站点的文字输入、PRINT、红心灵感、便签拖动，并检查浏览器可访问的样式、动画与 Web Audio 实现。

- 机身：圆角米色塑料、混凝土颗粒、底部厚度、内高光和地面投影。
- 黑色凹陷屏幕：VT323 字体、琥珀文字、闪烁块状光标；中文使用系统中文字体回退。
- 下方按钮：凹槽中的清空按钮、白色红心按钮、带物理按压位移的大 PRINT 按钮。
- 纸张：320px 原生宽度、Space Mono、锯齿边、ID／时间、虚线和斜纹条码、End of Transmission。
- 出纸：线性运动，`max(1500ms, 字符数 × 20ms)`。本项目按 Unicode 码点计数，避免 emoji 被算成两个字符。
- 打字：高通噪声点击（约 1200 Hz）与 100→50 Hz 三角波碰撞声。
- 回车：180→60 Hz 锯齿波滑落声、低通滤波和一次较重的机械点击。
- 原站打印声：500 Hz 锯齿波电机，40 Hz 方波调频、80 Hz 齿轮低鸣、3000 Hz 带通纸张噪声，以及结尾切纸声。

声音是 Web Audio 合成而非下载录音，噪声和音高含随机变化。复现的是声学结构与参数，不承诺跨浏览器、扬声器的逐采样一致性。

## 按 README 作出的调整

1. 机身严格使用 `rgb(229, 225, 214)`；PRINT 严格使用 `rgb(195, 102, 73)`，优先于原站网页中略有差别的颜色。
2. 默认音效为 README 要求的“噗噗噗”。想听参考站点音效，在右上角设置选择「热敏打印机」。音效名称已简化为「柔软气泡（默认）」「热敏打印机」「自定义音频」。
3. 不沿用原站写死的机身高度估算。测量真实打印机顶边与纸张高度，使纸张从正确位置出纸。去掉原来的 12px 底部空隙；出纸期间保持纸张平直，裁剪框底边严格对齐机身顶边，结束后恢复轻微旋转并按旋转包围盒底边贴边定位。
4. 长纸张会等比缩小，以确保整张纸留在可见画布中；超长内容的易读全文可以在历史面板查看。这是可见性与物理尺寸之间的明确取舍。
5. 加入历史、设置、静音、连接状态、键盘快捷键、触屏拖动和减少动画选项，保持机身正面布局简洁。
6. 不冒用 Gemini 服务标识。情话默认本地生成；诗词接 RDDH，歌词接 LRCLIB，统一由 Rust 数据层归一化。第三方不可用时用如实标注来源的本地备用。
7. 不复制原站无法完全显示的欢迎便签问题。欢迎便签是临时引导，不占用真实打印历史。
8. 点击或聚焦便签不显示红色虚线边框，键盘焦点仅轻微增加阴影。便签正文基准保持 14px，按最新反馈将输入屏幕从 23.52px 缩小为 20px；响应式布局仍会对机身或超长纸张整体缩放。
9. 设置增加独立的主题配色标签：奶油复古、晴空蓝（参考浅蓝机身／深蓝屏幕）、鼠尾草绿。语义色变量覆盖机身、按钮、屏幕、便签、背景、页眉页脚。所有主题的音量滑轨未填充部分统一恢复为浅灰色 `#dedbd2`。设置面板改为固定标题／分类标签，独立 `.settings-scroll` 内容区滚动，滚动条在标签下方开始且距底部／右侧留白；自定义下拉菜单跟随内容区滚动并在下方展开。九项颜色和四项文案可编辑；便签 Header 的 `{id}` 由实际编号替换，现有／新增便签同时更新，原始打印文字不改写。颜色覆盖按主题保存，可恢复当前主题默认值。

## 架构

```text
Web / CLI / HTTP client
        │ POST /api/print
        ▼
Axum handlers ── Printer::print (统一验证及打印命令)
                       │
                       ├── SQLx → SQLite WAL → 持久化便签
                       └── broadcast → SSE → 网页打印队列

Web / CLI → GET /api/print/random?type=poetry|lyrics|love&q=...
                      │
             RandomContentService
       请求 → 清洗 → 去重 → 缓存 → 换行
          ├── RDDH → 诗词字段映射
          ├── LRCLIB → 歌词字段映射与片段
          ├── InspirationProvider → 本地／自定义情话
          └── 上游失败 → 缓存旧内容／本地备用
                      │
       { type, title, author, content, source }
                      │
              预览 → POST /api/print
```

### 持久化和同步约定

- 打印成功写入 SQLite 后才广播事件；没有网页在线时也会保留记录。
- 每次 INSERT 原子地分配 `MAX(当前最高层级, 1000) + 1`，确保 Web／HTTP／CLI 并发打印均有递增且持久化的前景层级。浏览器还会考虑尚未保存的本地拖动层级，在出纸开始时将新便签置顶，必要时保存修正；刷新后不退回序号推算的旧层级。出纸裁剪区保留，前景层级不会破坏从纸槽露出的动画。
- 服务重启／网页重连时，SSE 先返回活动便签快照，不重新播放历史的声音和动画。
- 快照查询前先订阅广播，避免连接握手期间漏掉新打印；前端按 UUID 去重，避免 POST 响应和 SSE 产生两张纸。
- 同一网页按队列顺序出纸，不让多张纸同时挤出。
- 慢客户端的广播缓冲落后时，服务端重新发送活动便签快照。
- 拖动在本地逐帧渲染，放手时保存坐标和层级；其他网页收到更新后同步位置。多端同时拖动同一便签时使用最后写入的坐标。
- “×”仅把便签收起，不删除数据库记录；历史可放回桌面或创建一条新的打印记录。
- 纸张保存的是 CSS 像素坐标，换屏幕尺寸后会重新约束到当前画布，不保证不同设备上的绝对坐标完全相同。
- 自定义音频保存在当前浏览器 IndexedDB，偏好在 localStorage；不同浏览器／设备不共享音频。
- SQLite 是单机实例方案；多服务实例部署需要共享事件总线和数据库改造。

## API

### 打印

```http
POST /api/print
Content-Type: application/json

{"text":"想把今天的风，和一句喜欢你一起寄给你。","source":"http"}
```

返回 `201 Created` 和完整 `Note`。`source` 可省略（默认 `http`），最大 64 字节。

- 允许多行、制表符和首尾空格；纯空白会拒绝。
- CRLF 与 CR 统一为 LF。
- 最多 4000 个 Unicode 码点；其他控制字符会拒绝。
- 请求体最多 32 KiB；SQL 使用绑定参数。
- 验证错误为 `400`、便签不存在为 `404`、数据库失败为 `500`，这些业务响应使用 `{"error":"..."}`。
- 每次成功 POST 都代表一条新的打印命令，不提供跨请求幂等键；网络超时后重试可能创建新记录。

```json
{
  "seq": 1,
  "id": "82142e7b-2ba4-4002-9309-32b2073e3f28",
  "text": "Hello, paper.",
  "source": "http",
  "created_at": "2026-10-28T12:00:00+00:00",
  "x": null,
  "y": null,
  "rotation": 0.5,
  "z_index": 1,
  "archived": false
}
```

### 其他路由

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 健康检查 |
| GET | `/api/notes?limit=20&offset=0` | 历史，按 seq 倒序；limit 1–100 |
| GET | `/api/notes?archived=false` | 筛选仍在桌面的便签；省略 archived 则返回全部 |
| PATCH | `/api/notes/{id}` | 更新 `x`、`y`、`z_index`、`archived`，均可选；坐标必须成对提供 |
| GET | `/api/print/random?type=poetry` | 统一随机内容；type 默认 poetry，可选 love / lyrics；歌词 q 默认海阔天空；不自动打印 |
| GET | `/api/inspire?kind=love` | 旧兼容接口，仍返回 text/provider，内部复用统一数据层 |
| GET | `/api/events` | SSE：`sync`、`printed`、`updated`；15 秒保活 |

坐标范围为 0–100000 的有限数；z_index 为 1–2000000000 的整数。

### 替换灵感 API

```bash
NOTE_PROVIDER_URL=https://your-service.example/generate cargo run -- serve
```

服务端仅对情话向该地址 POST `{"kind":"love"}`，对方返回 `{"text":"生成的文字"}`。生成文本会验证长度、空白和控制字符，失败时返回本地内容。诗词／歌词分别使用 `POETRY_API_URL` / `LYRICS_API_URL` 可选镜像地址，固定附加标准参数。API 密钥不要写入前端。

### 第三方数据规范化与缓存

统一输出恰好五个字段：`type`、`title`、`author`、`content`、`source`。标题／作者来自上游，不臆造作者；空作者设为「佚名」或「未知歌手」。`GET /api/print/random` 无写库／打印副作用；打印前用统一 `print_text()` 格式化正文和作者／标题，Web 使用相同格式。

- RDDH：`hitokoto → content`、`from → title`、`from_who → author`、`source=poetry`。过滤其 `id=0` 且 `from=名言警句` 的固定兜底响应，不把它当作正常随机诗词。未提供的作者信息不臆造。
- LRCLIB：`trackName → title`、`artistName → author`、优先 `plainLyrics`，缺失则清洗 `syncedLyrics`。跳过纯音乐、空内容和重复结果；去掉 LRC 时间戳、metadata 和重复歌词行，随机选择一首及最多四行片段，`source=lrclib`。
- 内容：归一换行，移除不可见／非法控制字符，限制文本长度，再按 32 个等宽单元换行（中文计两个）。客户端使用 textContent，绝不把第三方文本作为 HTML 注入。
- HTTP：3 秒连接超时、6 秒总超时、最多 2 MiB 响应体，设置 LRCLIB 客户端 User-Agent。按说明接受诗词的字符串 ID，清理标题外层已有的《》以避免重复书名号。
- 诗词限流：RDDH 文档上限为 60 次／分钟，超限返回 429。单个服务进程内共享一个独立于缓存键的限流器，使用单调时钟维护 60 秒滑动窗口（最多 60 次），并强制至少 1.1 秒请求间隔留出安全余量。额度不足时不等待、不发起网络请求，直接使用缓存／本地候选。限流覆盖统一接口及旧兼容接口；缓存淘汰不会清除限流记录，多进程／多副本部署则需要 Redis 等共享限流存储。
- 缓存：以类型＋搜索词为键，最多 64 个键，每键最多 64 条。LRCLIB 批次 TTL 10 分钟；RDDH 每次访问尝试刷新一条随机内容，滚动保留历史候选。相同键的请求串行处理，其他键不受其网络等待阻塞。
- 失败：优先使用已有缓存（允许过期缓存），没有则使用本地公版诗词／原创歌词；来源分别为 `local:poetry`、`local:lyrics`，网页提示启用了备用内容。普通失败后该键 30 秒内不再请求上游；诗词 429 则触发全局冷却至少 60 秒，支持 `Retry-After` 秒数及 HTTP 日期，较短的后续冷却不会缩短已有冷却期限。
- 去重：缓存按标题、作者、清洗后的正文去重。诗词保存最近 16 条选择记录；即使上游 HTTP 成功但反复返回同一首，远程候选耗尽时也会从 21 条本地公版诗词补充未使用候选，来源仍标注 `local:poetry`，不循环输出唯一缓存项。歌词在多个候选时避免连续选择同一首。
- 缓存只在单进程内存中保存，重启清空，不影响打印历史。将来新增来源只需增加适配器，不改变打印服务或前端返回结构。
